## Attack path

Nmap scan revealed port 80, security dashboard. Web app enumeration with security snapshot, able to download results via data/[id] and download/[id]. Idor changing [id], credential capture via cleartext FTP. password reuse, SSH foothold. Priv escalation via getcap -r / 2>/dev/null revealed /usr/bin/python3.8 had the cap_setuid+ep capability set. Root.

---

## Recon

Nmap of ssh, telnet and ftp.

IDOR leaks FTP creds, tried SSH hoping for password reuse.

---

## Enumeration
visible ID in the URL, suspect IDOR, scripted a full sweep, include boundary values, filter results by content, only fall back to manual inspection once the automated sweep narrows the candidates.


---

## Foothold

Creds found via one protocol service should be tried on another exposed service, ie ssh in this case.

---

## Privilege escalation

Always check getpcap -r / 2>/dev/null as a standard part of priesc enumeration alonside SUID/sudo checks. Check GTFOBins for a ready made one liner for the specific interperter/capability combo found.

---

## Dead ends

chasing .git/config and robots.txt


---

## Lessons

VPN hygiene.
Full scan.
Always test boundary values.
Test known creds against every exposed service.
Always run privesc enumeration.
